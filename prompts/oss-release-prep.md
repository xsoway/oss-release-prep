# OSS Release Prep Prompt

把一个项目整理成符合 GitHub 开源要求的状态，并产出规范、详细、中英双语可切换的 README。以证据为准，把"可发布"拆成可勾选、可验证的检查项。

## 输入

- 目标项目路径或代码仓库。
- 已有 README / 文档 / 构建配置（如有）。
- 用户期望的详细度、语言与是否执行 git push / 建仓库等发布动作的授权边界。
- 可选：作者信息、License 偏好、版本号、项目定位描述。

先声明已知事实、信息缺口、冲突、范围外和最小假设。缺少关键信息（如作者、构建命令、技术栈）时，先标注缺口并按需问询或使用可验证的保守默认。

## 🔴 敏感信息红线（最高优先级，硬性阻断）

**严禁公开**任何密钥或敏感数据，优先于其它所有规则。

- **禁止公开**：LLM/各类 API key（`sk-…`、`sk-proj-…`、`sk-ant-…`、`ghp_…`、`xox…`、`AKIA…`）、token、cookie、私钥、密码、个人数据（真实姓名/邮箱/手机/地址/身份证）、绝对本机路径（`/Users/…`、`/home/…`）。
- **覆盖全部产物**：README、代码块、示例、gif/截图、日志、fixture、`examples/`、`references/`、检查记录——任何即将开源的文件都不得含密钥。`.env` 与凭据文件不得被 git 跟踪。
- **实施动作**：
  1. 勘察时即扫描目标项目的密钥模式，识别 `.env`/凭据文件/已跟踪的敏感文件。
  2. 生成任何产物前再次自检：无真实值、无"改几个字符的伪示例"，示例一律用无意义占位符（如 `sk-YOUR_KEY_HERE`、`<token>`）。
  3. 对全部 `.md`/`.yaml`/`.yml` 跑密钥正则扫描，零命中才交付；结果记入检查记录与交付说明。
- **命中即阻断**：发现任何敏感信息 → **立即中止发布**，先移除密钥、轮换已泄露的凭据、用 `git filter-repo` 等清除 git 历史，重扫通过后再继续。
- **不因未发布而豁免**：即使尚未推送，敏感信息规则同样生效，不得写入任何将要共享的文件。

## 你要做的事

1. **勘察项目**：目录结构、构建/测试命令、依赖与运行环境、git 状态、现有 README / License / 忽略规则、是否存在敏感文件。
2. **逐项检查**：按 `references/release-checklist.md` 核对缺失工件、敏感信息、绝对路径、License、README 结构等，并记录证据。
3. **补齐缺失**：按需创建/修复 `LICENSE`、`.gitignore`、`.gitattributes`、缺失的 README 章节、徽章、目录结构说明。
4. **生成/改写 README**：中英双语，各自独立文件 + 顶部切换链接；English 版与中文版结构逐节镜像，内容按用户要求详尽。结构基准参照 `references/readme-style.md`。全程执行「敏感信息红线」。
5. **推广面与社区**（如适用）：配置仓库 About / topics（`ai`、`llm`、`skill`、`persona`、`self-memory` 等），启用 GitHub Discussions，制作并链接项目主页（gruvbox-material 黑金风格、中英切换）。
6. **发布产物与门禁**（如适用）：用 `uv build` 产出 sdist/wheel 并附为 release assets；若更新了 make-code-clean / code-review-graph 等监管工具，先做一次外部 reviewer 代码审查再发布。
7. **验证**：运行可执行的校验脚本（如包结构、链接、敏感信息扫描），区分"静态检查通过"与"已发布/已验证行为"。除非用户显式要求，不执行 git push / 创建远程仓库。

## 执行规则



- 以证据为准：每个检查项都必须有可引用的事实（命令输出、文件存在、git 状态、代码位置）。缺证据即视为未通过，并给出下一步。
- 不强造内容：项目技术事实（构建命令、依赖、结构）不沿用外部项目约定，也不虚构 README 里无法验证的安装/运行步骤。
- 双语一致性：两个 README 覆盖同一组主题；切换链接 `README.md ↔ README.zh-CN.md` 互指正确。
- 敏感信息红线（见上）：命中即阻断发布，绝不把密钥/个人数据/绝对路径放进任何产物。
- 证据分层：静态检查、结构校验、实际运行、发布动作分别报告；任何一步未执行都如实标注。
- 发布动作须授权：git push、创建远程仓库、gh 操作等仅在用户明确要求时执行。

## README 结构基准

参照 `references/readme-style.md`，推荐包含（按项目实际情况取舍）：
- 顶部居中徽章区（版本 / License / 状态 / 语言等）。
- 标题 + 一句话定位。
- 语言切换链接（README.md 放"中文"，README.zh-CN.md 放"English"）。
- 目录（Table of Contents）。
- 是什么 / 为什么需要。
- 核心概念或特点（如适用）。
- 目录结构（代码块树 + 逐文件职责，如适用）。
- 快速开始：环境要求、安装、构建、测试命令与预期输出。
- 功能 / 用法 / 配置说明。
- 集成或扩展点（如适用）。
- 安全边界 / 设计原则。
- FAQ。
- 路线图。
- 贡献指南。
- License。
- 维护者。

## 最低覆盖清单

- [ ] 勘察完成：结构、构建/测试命令、git 状态、依赖已确认。
- [ ] 敏感信息红线执行：密钥/个人数据/绝对路径扫描零命中，`.env`/凭据未被跟踪。
- [ ] 检查表逐项核对，每项有证据或明确标注未完成。
- [ ] README 中英双语独立文件，切换链接互指正确，结构逐节镜像。
- [ ] 无真实密钥、个人数据、绝对本机路径；无伪造的安装/运行结论。
- [ ] 发布相关动作（git push / 建仓库）仅在用户显式授权时执行。
- [ ] （如适用）About / topics / Discussions / 项目主页已配置并验证，主页为 gruvbox-material 黑金风格且支持中英切换。
- [ ] （如适用）release 已附 `uv build` 产出的 sdist/wheel 等可下载 assets，且 `dist/` 通过敏感信息扫描。
- [ ] （如适用）发布质量门禁：更新监管工具后已做一次外部 reviewer 代码审查。
- [ ] 交付说明含：做了什么、如何验证、产物路径、风险/回滚、复盘结论。

## 输出

输出说明本次改动与补齐项、README 路径与结构变更、检查表的通过/未完成项及证据、敏感信息扫描结果、为运行/未运行的校验命令、风险与回滚方式。默认 Markdown。

## 质量要求

- 不堆砌与项目无关的宣传或无法验证的承诺。
- 每个 README 中的安装、构建、测试、运行步骤都必须能在项目里找到依据。
- 双语版本信息一致；技术命令/结构共享，叙述各自独立。
- 敏感信息与绝对路径绝不进入任何产物；发现即阻断并清理。
- 未授权的发布动作绝不触发。若代码在发布前应做真实构建/测试验证，先运行并以结果作为"可发布"证据；无法运行则明确报告未运行原因与风险。
